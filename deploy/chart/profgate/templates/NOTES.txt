profgate {{ .Chart.AppVersion }} is installed as {{ include "profgate.fullname" . }} in namespace {{ .Release.Namespace }}.

Check these three things first.

1. The gateway is Ready. /readyz turns 200 only once the informer caches have
   synced{{ if .Values.pgo.enabled }} and the NATS stores have opened{{ end }}, so a Pod that stays unready is
   reporting a real problem rather than a slow start:

     kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "profgate.fullname" . }}
     kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "profgate.fullname" . }}

2. The realms. Authentication is disabled, so every request is granted the
   realm named by auth.anonymousRealm, which is {{ .Values.auth.anonymousRealm }}. This release grants it:

{{- range $name, $realm := .Values.realms }}
     {{ $name }}: namespaces {{ $realm.namespaces | join "," }} | services {{ $realm.services | join "," }} | profiles {{ $realm.profiles | join "," }}
{{- end }}

   A realm listing "*" reaches every Service the ClusterRole can see. Narrow
   it before the gateway is reachable from outside the cluster.

3. Reach the API through the Service, which carries the API port only:

     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "profgate.fullname" . }} 8080:{{ .Values.service.port }}
     curl localhost:8080/v1/targets?namespace=<ns>&service=<svc>

{{ if .Values.pgo.enabled }}
PGO collection is on. The gateway does not create its NATS stores, its account,
or its credentials: it opens them at startup and exits when one is missing.
This release expects the Secret {{ .Values.nats.existingSecret }} in namespace {{ .Release.Namespace }}, holding key
{{ .Values.nats.secretKey }}, mounted at {{ .Values.nats.credsFile }}, against {{ .Values.nats.url }}.

     kubectl -n {{ .Release.Namespace }} create secret generic {{ .Values.nats.existingSecret }} \
       --from-file={{ .Values.nats.secretKey }}=profgate.creds

Provision the buckets and the account first; deploy/nats/README.md in the
source repository holds the commands.

Create the Secret first. Startup validation opens the file nats.credsFile
names, so a gateway that cannot find it exits and the Pod restarts in a loop.

With the credentials in place and NATS unreachable, the Pod runs and never
becomes Ready. A rollout stalls there rather than replacing a working replica,
which is the safe failure and does mean a NATS outage blocks upgrades.
{{- else }}
PGO collection is off. Nothing in this release talks to NATS, and the memory
limit is the static {{ .Values.memoryLimitWithoutPGO }} rather than the figure derived from pgo.limits.
{{- end }}
